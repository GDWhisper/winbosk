### Step 1 — `crates/core/src/shell_items.rs`（新建）

```rust
//! 虚拟壳项（无文件系统路径的桌面项，如回收站）的 id 口径与隐藏判定——纯逻辑，零 OS 依赖。

/// 虚拟壳项 id 前缀。生成在 shell（item_id），消费在 core（整理候选集）与 app（移出拒绝）。
pub const VIRTUAL_ID_PREFIX: &str = "shell:";

/// 是否虚拟壳项 id。**不要**用 `Icon.path.is_none()` 代替——那会把将来"无路径的拖入项"误判。
pub fn is_virtual_id(id: &str) -> bool {
    id.starts_with(VIRTUAL_ID_PREFIX)
}

/// 注册表三态。None 与 Some(false) 语义不同，禁用 Option<bool>。
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum PolicyValue {
    Unset,    // 键不存在
    Enabled,  // 显式 0
    Disabled, // 显式 1
}

impl PolicyValue {
    /// DWORD → 三态。非 0/1 的脏值按 Enabled（不隐藏）处理，不 panic。
    pub fn from_dword(v: Option<u32>) -> Self {
        match v {
            None => Self::Unset,
            Some(0) => Self::Enabled,
            Some(1) => Self::Disabled,
            Some(_) => Self::Enabled,
        }
    }
}
```

`policy_hidden` 的四态口径（单测就按这张表断言）：

| HKCU | HKLM | `policy_hidden` |
| :--- | :--- | :--- |
| `Disabled`(1) | 任意 | **true**（用户隐藏优先于一切） |
| `Enabled`(0) | `Disabled`(1) | **false**（用户显式显示，压过机器策略） |
| `Unset` | `Disabled`(1) | **true**（机器策略隐藏） |
| `Unset` | `Unset` | **false**（不隐藏；**但不等于"获得准入"**） |

```rust
/// 是否被「显式隐藏」。**只回答"准不准"，不回答"能不能"**——缺值返回 false 不代表允许显示。
pub fn policy_hidden(clsid: &str, hkcu: PolicyValue, hklm: PolicyValue) -> bool {
    match hkcu {
        PolicyValue::Disabled => true,
        PolicyValue::Enabled => false,
        PolicyValue::Unset => hklm == PolicyValue::Disabled,
    }
}
```

`clsid` 参数**本切片不用**（白名单只有 1 条，直接在调用处比对）；保留是为将来按 CLSID
批量查询时不改签名。若 clippy 报 unused，改为 `_clsid` 并在文档注释说明。

**单测**（`#[cfg(test)] mod tests`，全部内存瞬时）：上表 4 行 + `from_dword(None/0/1/7)` 4 行 +
`is_virtual_id` 3 行（虚拟 id true、普通路径 false、**无路径但非 `shell:` 前缀 false**）。

### Step 2 — `crates/shell/src/virtual_items.rs`（新建）

```rust
//! 虚拟壳项的注册表裁决 + PIDL 复刻。**唯一允许碰注册表 / PIDL 的虚拟壳项代码**。

/// 本切片只镜像回收站。CLSID 大写。放白名单 ≠ 一定显示，还要过策略闸与注册探针。
pub const MIRRORABLE_VIRTUAL_ITEMS: &[&str] = &[
    "{645FF040-5081-101B-9F08-00AA002F954E}", // 回收站
];

pub struct VirtualItemSnapshot {
    pub parsing_name: String, // ::{645FF040-…}
    pub clsid: String,        // {645FF040-…} 大写
    pub display_name: String, // 回收站
}

/// 读注册表（只读 KEY_READ）。键路径：
/// Software\Microsoft\Windows\CurrentVersion\Explorer\HideDesktopIcons\
///   {NewStartPanel, ClassicStartMenu}
/// 键不存在 / 类型不符 / 被锁 → PolicyValue::Unset。
pub fn policy_value(hive: HKEY, clsid: &str) -> PolicyValue;

/// 当前应镜像的虚拟项快照。**成本**：只做注册表读（1 条 × 2 hive = 2 次 RegGetValueW，
/// 本机实测约 20 µs 量级）。**禁止**在这里调 `IShellFolder::EnumObjects`
/// （全量枚举实测 11.9~14.9 ms，会把 4~7 ms 的心跳预算撑爆）。
///
/// 判定 = 白名单准入 && !policy_hidden(…)。**只在启动与用户点"刷新"时调用。**
pub fn mirrorable_virtual_snapshot() -> Vec<VirtualItemSnapshot>;

/// PIDL 句柄；Drop 时 CoTaskMemFree。
pub struct VirtualItemHandle { pub pidl: *mut ITEMIDLIST }
impl Drop for VirtualItemHandle { /* CoTaskMemFree */ }

/// SHParseDisplayName(parsing_name) → PIDL。失败返回 None（调用方记日志并跳过）。
pub fn virtual_item_handle(parsing_name: &str) -> Option<VirtualItemHandle>;

/// 真实"打开"：ShellExecuteEx + SEE_MASK_INVOKEIDLIST(0xC) + lpIDList。
/// 成功判据 = hInstApp > 32（HINSTANCE 口径，不是 GetLastError）。失败记日志。
pub fn open_shell_item(pidl: *const ITEMIDLIST) -> bool;
```

**`crates/shell/src/lib.rs`**：加 `pub mod virtual_items;` 并写一句分层说明（它为什么在 shell）。

**`crates/shell/src/items.rs`** 改两处：

1. `item_id`(262)：虚拟项回退改为
   `format!("{VIRTUAL_ID_PREFIX}{}-{}", display_name.to_lowercase(), clsid[1..9].to_lowercase())`
   —— CLSID 从 `build_item`(170) 里额外取一次 `SHGDN_FORPARSING`(0x8000) 解析名后切出
   （`::{XXXX-…}` 的第 1..9 位）。**只对虚拟项调**（有路径项仍走 `SHGetPathFromIDListW`）。
   实测成本：9 项合计 4.7~13.1 µs，单项 0.5~1.5 µs，可忽略。
2. `DesktopItem::launch`(50)：改为返回 `Result<(), String>`。
   - 有路径 → 原 `ShellExecuteW` 路线；
   - 无路径且 `pidl` 非空 → `virtual_items::open_shell_item(pidl)`；
   - 两者都不可用 → `Err(..)`。
   **不留丢弃错误的薄包装**（plan 10 §8.6：全仓 `.launch()` 唯一调用点是
   `crates/app/src/main.rs:2273`，"改 6 个调用点"的理由不存在；薄包装会把失败变回静默）。

**单测**：`item_id` 新口径（两个控制面板 id 不同、回收站 id 含 `645ff040`）；
`kind_from`(229) 对虚拟项仍返回 `ItemKind::Unknown`（不回归）。

### Step 3 — `crates/app/src/file_ops.rs`

**新增 `sync_virtual_items`**（App 层独立入口，**不经过 `reconcile_fences`**，H1）：

```rust
/// 虚拟壳项一次性同步：注册 / 移除 / 清池。**只在启动与控制中心"刷新"时调用。**
/// 绝不要挂进 SyncLibrary(4s)，也绝不要并进 reconcile_fences——理由见 H1。
pub(crate) fn sync_virtual_items(rt: &mut Runtime, snap: &[VirtualItemSnapshot]) -> bool
```

三步，顺序固定：

1. **清池（先清后注册）**：删掉 `desk.icons` 里 `ic.path.is_none() && is_virtual_id(&id)`
   && `id` 不在 `snap` 推导出的 id 集合里的条目；同步清 `rt.items`（按 id 反查下标）
   与 `rt.bitmap_ids`，并重建 `rt.item_index`。
   ⇒ 中文名 / 英文 locale 名 / 任何旧口径都被这一条覆盖（H3）。
   **现网已有 15 条死元数据**，这一步会一次性清掉，属预期。
2. **注册**：`snap` 里未被任一栅栏持有的项 → `register_virtual_item(rt, fence_idx, &s)`。
   目标栅栏 = 桌面栅栏；定位**复用** `resolve_desktop_fence(&rt.desk, None)`
   （`crates/app/src/main.rs:2377`，语义 = title=="桌面" 或 storage==桌面目录），
   为 `None` 则跳过并 warn（本切片不兜底创建新栅栏）。
3. **移除**：栅栏成员里 `is_virtual_id(id)` 为真但不在快照里的 → 从成员移除
   （**不删任何磁盘内容**——它们本来就不在磁盘上）。

**新增 `register_virtual_item`**：建 `DesktopItem{ kind: Unknown, path: None, id: H5 口径 }`
与 `Icon{ path: None }`（H4），然后走 `register_fence_item`(70) 的**同款事务**：
`items` / `item_index` / `bitmap_ids` / `pending_uploads` 同帧对齐，
位图槽走 `rt.bitmap_ids.values().max()+1`（单调递增，与 file_ops.rs:96 同口径，
**不要**用 `rt.items.len()`）。
抽图失败只 warn，不阻断注册。

**改 `remove_fence_icon_by_id`(2294)**：函数首行加
`if is_virtual_id(id) { tracing::info!(id, "虚拟壳项不支持移出栅栏"); return; }`
（§3-6 的行为落点；`remove_fence_icon` / `remove_selected` 都经它，天然覆盖）。

**不改**：`mirror_linked_fence` / `mirror_converged` / `mirror_existing_paths` / `reconcile_fences`（H1/H2）。

**单测**（`file_ops.rs::tests`，纯内存）：

| 场景 | 期望 |
| :--- | :--- |
| 池里有 `shell:控制面板`(旧口径) + `shell:This PC`(英文) + 注册新口径 `shell:控制面板-5399e694` | 旧键全清（池/items/bitmap_ids），新键就位 |
| **心跳回归（H1 锁）**：Desk 已含虚拟项成员，`mirror_converged` 入参仍按磁盘口径计算 | 返回 **true**，早退生效，不进注册循环 |
| 桌面文件被删 + 虚拟项在场 | 文件项回收，虚拟项保留 |
| `register_virtual_item` 后 | `ic.path.is_none()`；`is_managed_path(rt, Path::new("::{645FF040-…}")) == false`（H4 锁） |
| `remove_fence_icon_by_id("shell:…")` | 池不动、`free_icons` 不增、栅栏成员不变 |
| `sync_virtual_items` 连续两次 | 第二次返回 `false`（幂等，0 变动） |
| 桌面栅栏不存在（`resolve_desktop_fence` → None） | 不 panic、不创建栅栏、返回 false + warn |

### Step 4 — `crates/core/src/model.rs`（候选集排除）

在 `auto_organize_all`(976) 与 `organize_icons_by_rules`(911) 的候选收集处各加一行：

```rust
if crate::shell_items::is_virtual_id(id) { continue; }
```

**为什么不能省**：候选 = `free_icons` + 桌面栅栏里所有不匹配自身 rule 的成员 ⇒ 回收站天然是候选。

**单测**：`auto_organize_all` 候选含回收站时，回收站仍在桌面栅栏、`moved_icons` 不含它；
同一条对 `organize_icons_by_rules` 也成立；再加「用户栅栏 `name_patterns=["回收站"]`」这条硬回归。
